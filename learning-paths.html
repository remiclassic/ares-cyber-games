Instrumenting the Ares games for learning paths

The goal is not to choose where each game goes. It is to make every game measurable and controllable, so that any learning path that includes one can gate on performance, target specific levels, and keep a record of every attempt.

Current scope. This page replaces the initial plan, which mapped each game to items in the nine full-release learning paths. That map is kept as the first idea and as a source of examples.

"I would like to instrument the minigames so that if there were a learning path that incorporated them, we would be able to do so in a way that had measurable completion gates (achieve this score/level of performance) or targeted content (do this level and this level) and a recorded attempt record."Brad, on direction for the games

Three capabilities every game will have

01 · Attempt record

Every play is recorded, start to stop

An attempt opens when the learner presses Start and closes however the play ends: finished, gate reached, stopped by the platform, learner left, or timed out. Closing the tab still closes the attempt. A retry is a new attempt.

For example: 3 attempts, best score 84, passed on attempt 2, 11 min in total.

02 · Completion gate

Pass on performance, not just on finishing

The path sets the bar: a score, a number of levels cleared, or a specific level passed. The checkpoint questions inside the game (the learning evidence) can also be required. The game reports whether the gate was met and by how much.

For example: "Score 80 or more, and pass the stolen-account case."

03 · Targeted content

Play exactly the levels the path needs

Every game publishes a list of its levels with stable IDs. A path can start at a level, play only a chosen set, and switch the tutorial off for learners who have seen it.

For example: "Play only Insider or Accident cases 3 and 5."

How it works

The games run in an iframe and already talk to their host with postMessage. One shared module will handle all three capabilities the same way in every game, so the platform integrates once rather than 36 times.

What the path sends when the game opens

ares:host:init {
  activityId: "insider-or-accident",
  levels:   ["case-3", "case-5"],    // targeted content
  startAt:  "case-3",
  gate: {                            // completion gate
    scoreAtLeast: 80,
    mustPass:     ["case-5"],
    evidence:     "all-correct"     // optional
  },
  stopWhenGateMet: true,
  mode: "assessed",                  // or "practice"
  skipTutorial: true
}

What the game sends back when the attempt ends

ares:game:attempt-ended {
  attemptId:  "a7f3…",
  activityId: "insider-or-accident",
  startedAt:  "2026-11-19T15:02:11Z",
  durationSeconds: 412,
  reason: "completed",   // gate-met | stopped
                         // | quit | timeout
  levelsPlayed: ["case-3", "case-5"],
  levelResults: [
    { id: "case-3", score: 90, passed: true },
    { id: "case-5", score: 78, passed: true }
  ],
  score: 84,             // 0–100 across the game
  gate: { met: true, failedOn: [] },
  evidence: { asked: 4, correct: 3 }
}

The game also sends ready (its version and level list, so Studio can show authors a picker), attempt-started, and level-ended after each level, so the platform can track progress during a long game. ares:host:stop ends a game at once, and the attempt is still recorded. Scores are reported both as a 0–100 figure and in the game's own units, so the same gate works across games.

Where the games stand today

CapabilityTodayWhat's missing
Attempt start and finishPartialAll games report start, key actions and completion. None reports quitting or closing the tab, and retries don't get their own attempt ID.
Per-level resultsPartialResults are computed per round or case inside each game but only reported once, at the end, and in a different shape per game.
Score on one scaleNot yetEach game scores in its own units. Each needs a mapping to 0–100.
Completion gateNot yetNo game takes a gate from the host.
Targeted levelsPartialSeeds work, and Alert or Noise and Breach Timeline have short modes. No game takes a level list from the host yet.

Studio sideNot yetStudio has a Minigame item type, but it only takes a title and a description. It needs fields for the game link, levels, gate and mode, and somewhere to store attempt records. This is for the platform team.

Plan

  1. Shared instrumentation module. Build one module that handles attempts, gates, levels and stop, with tests, and agree the message shapes with the platform team before the games adopt it.
  2. Host simulator page. A test page that acts as the platform: pick a game, set its levels and gate, play it, and see the attempt record. The platform team can build against it without Studio, and it doubles as the demo.
  3. Pilot on three games. Insider or Accident (cases), Patch Tuesday (rounds) and Alert or Noise (timed, range-wait). They cover the three level shapes the games use.
  4. Team playtest with Eric. Five to eight people play the pilot games through the simulator, with gates switched on. Check that the records and gates match what testers experienced.
  5. Roll out to the rest. Each game declares its levels and its 0–100 score mapping. That is a small adapter per game.

What this makes possible

These are illustrations, not a placement plan. The full game-by-item map is in the initial plan. These examples are taken from the nine Full release learning paths in Studio to show the kind of gate and targeting a path author could set once the games are instrumented.

Example gates in today's learning paths

Cybersecurity Basics, after Subnet Masks: Bit by Bit, subnet sizing levels only. Gate: score 80 or more.

Digital Forensics Introduction, before KAPE Escape: Insider or Accident, insider-staging cases only. Gate: pass each case and get the checkpoint questions right.

Defensive Cybersecurity Introduction, before Elite Hackers: Pattern Patrol, detection levels. Gate: no false positives on the final level.

Real World Exploits, after SolarWinds: Vendor Vetting, the software-supplier purchase. Gate: the supplier is approved with conditions or rejected, and never approved outright.

Networking Hands-on Labs, while a range loads: Alert or Noise, 30-second mode, no gate. The platform stops it when the range is ready, and the attempt is still recorded.
